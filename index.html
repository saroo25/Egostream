EGOSTREAM

A Diagnostic Benchmark for Streaming Episodic Memory in Egocentric Vision

Rosario Forte, Giuseppe Lando, Antonino Furnari

Co-AI Research Group, Department of Mathematics and Computer Science, University of Catania

EgoStream is a streaming video benchmark for episodic memory: it measures what a multimodal LLM remembers from a first-person video stream, for how long, and when an answer stops being valid as the world changes. It ships with a unified framework to compare KV-cache memory-management policies under one protocol.

Benchmark

Streaming recall, measured carefully.

Each question is grounded in a specific evidence moment, assigned a memory category and asked again at several delays inside its Answer Validity Window. The result is a diagnostic profile of what a streaming model retains and when it forgets, not a single aggregate score.

Memory dimensions

What, where, when, how, who, why, and what next.

Questions are organised along seven dimensions of episodic memory, building on Tulving's account of episodic memory and on cognitive work on spatial, temporal, event, social, causal and prospective memory. Each question receives one primary label and optional secondary tags.

Answer Validity Window

Validity matters.

The AVW is the span, after the last evidence moment, during which the annotated answer stays factually correct. Query times are sampled only inside it, so a wrong answer means the model forgot, not that the world moved on. Every window was reviewed by humans; 1.96% needed adjustment.

Streaming protocol

Only what was seen so far.

Models process frames sequentially at 1 FPS and keep a compact internal memory. The question is revealed only at recall time, after the ingestion of the stream up to that timestamp, so memory management cannot peek at the query.

Recall regimes

A log-scaled view of memory, grounded in memory science.

Delays follow the classical paradigm of probing memory at several retention intervals, from Ebbinghaus' forgetting curve to consolidation timescales, so that the same question can test working memory and long-term retention.

Results

Same accuracy, different memories.

Twenty-one memory-management policies were run on a frozen Qwen3-VL-8B under a 9,804-token active-cache budget (1 FPS, 896×512 frames, single A100), with the ranking confirmed on InternVL 3.5-8B and Molmo 2-8B.

Key findings

No in-cache policy exceeds about 45%.

A plain sliding window scores 29.53% semantic / 28.33% temporal accuracy; protecting the system prompt as sink tokens (StreamingVLM) lifts it to 44.74% / 39.05% at the same latency.

Adaptive head budgets (Ada-KV) give the best semantic average, 45.88%, with the best detail retention (57.04%); intra-frame cosine pruning reaches 45.63% with the best spatial retention (60.51%) at 2.28 s per frame.

Pruning beats merging on every backbone: discarding redundant tokens preserves fine-grained details and temporal structure, averaging blurs them (45.12% vs 41.87% with the pseudo-attention scorer).

Quantized offloading with retrieval (StreamingTOM) is the fastest policy, 1.43 s per frame, and rescues ultra-long-term recall (34.21%) at a small cost in average accuracy (42.86%).

Pre-prefill token compression (STC) reaches 47.18% semantic accuracy at 0.23 s per frame, above every in-cache policy; a text-only baseline scores 25.42%, chance level, so the questions cannot be solved from priors.

Budget matters with diminishing returns: 2.6K to 9.8K tokens raises semantic accuracy from 40.88% to 45.19%; 50.8K tokens peaks at 47.08% while nearly tripling processing time.

Framework

One KV cache, every memory policy.

The released code isolates memory management as the only variable: the vision encoder, projector, decoder and prompts stay fixed while a plug-in memory manager operates on the mutable region of the cache. One JSON file describes each experiment of the paper.

Policies

Sliding window, sinks, pruning, merging

FIFO, attention sinks, protected recent frames, intra- and inter-frame pruning with cosine, pseudo-attention, value-norm and sink-guided scorers, token merging, composable pipelines.

Policies

Ada-KV, offloading, retrieval, STC

Adaptive per-head budgets, disk and int8 quantized offloading with ReKV-style retrieval at question time, StreamingTOM-like pipelines and STC pre-prefill compression.

Backbones

Qwen3-VL, InternVL 3.5, Molmo 2

The backbone is chosen from the config; the same runner, protocol and budget apply to all three families.

Configs, evaluation, data scripts

FAQ

Questions people ask about EgoStream.

What is EgoStream?

EgoStream is a diagnostic benchmark for streaming episodic memory in egocentric vision, published at NeurIPS 2026 (Track on Evaluations and Datasets). It contains 2,250 curated questions about first-person videos, organised in seven memory dimensions and expanded into 8,528 recall-conditioned evaluations, together with a unified framework that compares KV-cache memory-management policies in streaming multimodal LLMs.

Is EgoStream a streaming video benchmark?

Yes. Models must process the video sequentially and answer each question using only the frames observed up to the query time, while keeping a compact internal memory instead of an unbounded frame buffer. Ingestion is query-agnostic: the question is revealed only at recall time.

Which KV-cache memory-management methods does EgoStream evaluate?

Sliding windows (FIFO), attention sinks, protected recent-frame tokens, intra-frame and inter-frame token pruning (cosine redundancy, pseudo-attention, value norm, sink-guided attention), token merging, Ada-KV adaptive head budgets, disk offloading and int8 quantized offloading with retrieval, and pre-prefill token compression (STC). They reproduce the behaviour of StreamingVLM, StreamMem, InfiniPot-V, StreamingTOM, ReKV, CaM and Ada-KV inside one KV-cache implementation.

What is the Answer Validity Window (AVW)?

The AVW is the time span, after all the evidence for a question has been seen, during which the annotated answer remains factually valid as the scene keeps changing. Sampling query times inside the AVW lets EgoStream measure forgetting without confusing it with answers that became obsolete.

What are the recall regimes?

Seven log-spaced delays between the end of the evidence and the question: instant (0 s), short (0-5 s), short-mid (5-30 s), mid (30 s-3 min), mid-long (3-30 min), long (30 min-8 h) and ultra-long (over 8 h). They follow memory-consolidation timescales from cognitive science, from working memory to hippocampal-cortical transfer.

Which memory dimensions are tested?

Detail (what), spatial (where), temporal (when), event (how / did it occur), social (who), causal (why) and prospective (what next). The taxonomy follows the classic episodic-memory framework of Tulving and later work on spatial, temporal, event, social, causal and prospective memory.

Which source datasets are the questions built from?

Ego4D Episodic Memory VQA (498 questions), EgoLife (433), EgoTempo (425), Multi-Hop EgoQA (578) and HD-EPIC (316). Every question was validated by human annotators; videos stay with the original datasets and are never redistributed.

How does EgoStream differ from EgoSchema, StreamingBench or EgoLifeQA?

Those benchmarks cover at most some of the following: egocentric video, online streaming, evidence grounding and a memory taxonomy. EgoStream is the only one that combines all four with Answer Validity Windows and multiple recall regimes per question, so that it measures what is remembered and for how long rather than only aggregate accuracy.

What do current models score on EgoStream?

On Qwen3-VL-8B with a 9,804-token budget the best in-cache policies reach about 45% semantic accuracy (Ada-KV 45.88%, intra-frame cosine pruning 45.63%), against 29.53% for a plain sliding window and 25.42% for a text-only baseline; every in-cache policy runs slower than real time (more than 1 s per frame on an A100).

Is the data available?

The streaming framework, every run configuration of the paper and the data preparation scripts are released on GitHub. The question annotations will be published on this page; videos must be obtained from the five source datasets under their own licenses.
